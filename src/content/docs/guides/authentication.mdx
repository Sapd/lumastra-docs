Lumastra has three ways to sign in. You can use them side by side. The iPhone, iPad and
Apple TV apps work with all three: the user approves a code in a signed-in browser.

| Method | Pick it when |
| --- | --- |
| Built-in accounts | You have no identity provider. Nothing to set up. |
| OIDC | You have a provider such as Authentik or Keycloak. The simplest single sign-on. |
| Forward auth | Your reverse proxy already signs users in. |

## Built-in login

The setup wizard creates the first admin with a username and password. Users sign in at
`/login`. Sessions last 30 days (`NATIVE_AUTH_SESSION_TTL_DAYS`). Passwords are hashed with
scrypt, and sign-in is rate-limited with account lockout. There is no built-in MFA. Admins
add accounts and reset passwords at **Admin → Users**. There is no email reset. If you lock yourself out, set a new password from the host. It prints one
and signs that user out everywhere:

```bash
docker compose exec lumastra npx tsx --tsconfig tsconfig.scripts.json scripts/reset-password.ts <username>
```

## Set up Authentik

These steps use Authentik as an OIDC provider. Lumastra must be reachable over HTTPS with
`ORIGIN` set (see the [Reverse proxy guide](/guides/reverse-proxy/)).

1. In Authentik, open **Directory → Groups** and create a group such as `lumastra-admins`.
   Add yourself to it.
2. Create an application with an **OAuth2/OpenID provider**. Set the client type to
   confidential. Set the redirect URI to `https://media.example.com/auth/oidc/callback`,
   matched exactly, with your own address.
3. Select the scopes `openid`, `profile` and `email`. Make sure the ID token carries the
   user's groups in a `groups` claim. If the built-in mappings do not, add a scope mapping
   that does.
4. Copy the client ID and the client secret. The issuer URL has the form
   `https://auth.example.com/application/o/<application-slug>/`.
5. Add the settings to `.env`. Use your own values:

   ```bash
   cat >> .env <<EOF
   AUTH_OIDC_ENABLED=true
   AUTH_OIDC_ISSUER=https://auth.example.com/application/o/lumastra/
   AUTH_OIDC_CLIENT_ID=<client id>
   AUTH_OIDC_CLIENT_SECRET=<client secret>
   AUTH_OIDC_PROVIDER_NAME=Authentik
   ADMIN_GROUPS=lumastra-admins
   EOF
   docker compose up -d
   ```

6. Open `https://media.example.com/login`. You should see **Sign in with Authentik**.
   Sign in with the account from step 1. On a fresh install, use `/setup` instead: the
   first account becomes admin only if it is in an `ADMIN_GROUPS` group.

Later users are created at their first sign-in. A user in an `ADMIN_GROUPS` group becomes
admin. Group sync only promotes: removing a group never silently removes admin. An admin
can pin a user's status at **Admin → Users**. On Kubernetes, see the `auth.oidc` values in
[Advanced Kubernetes](/guides/deploy-kubernetes-advanced/#how-do-i-set-up-sign-in).

## If you use another OIDC provider

Register the same redirect URI and set the same variables. On plain HTTP, built-in sign-in
still works, but OIDC needs `ORIGIN` set to that `http://` address. Provider differences:

- **Keycloak:** groups arrive as `realm_access.roles`. Set
  `AUTH_OIDC_GROUPS_CLAIM=realm_access.roles` and `AUTH_OIDC_SCOPES=openid profile email roles`.
- **Google:** tokens carry no groups, so every user starts as non-admin. Promote them at
  **Admin → Users**.
- **A public client with no secret:** leave `AUTH_OIDC_CLIENT_SECRET` out.

Optional settings:

```dotenv
AUTH_OIDC_SCOPES=openid profile email   # must include openid
AUTH_OIDC_GROUPS_CLAIM=groups           # a dot path works for nested claims
AUTH_OIDC_LINK_BY_VERIFIED_EMAIL=true   # link a first sign-in to an account with the same verified email
AUTH_OIDC_LINK_BY_USERNAME=false        # less safe; only for moving from built-in accounts
```

**The provider uses a private CA.** The server calls the provider itself, so it must trust
the certificate. Mount the CA file, readable by user 1000, and set it:

```yaml
services:
  lumastra:
    environment:
      NODE_EXTRA_CA_CERTS: /certs/idp-ca.crt
    volumes:
      - ./certs/idp-ca.crt:/certs/idp-ca.crt:ro
```

The provider's host name must also resolve inside the container. A `*.localhost` name
never does. The setup wizard's **Test connection** names the cause of a failure.

**Signing out at the provider should end the Lumastra session.** Set the provider's
back-channel logout URL to `https://media.example.com/auth/oidc/backchannel-logout`. No
Lumastra setting is needed. `AUTH_OIDC_BACKCHANNEL_LOGOUT_CASCADE=true` also revokes the
user's device tokens.

## If you use forward authentication

Your proxy signs the user in and sends the name and groups as headers. Lumastra believes
them only when you turn it on and only from known proxies. Add to `.env`, with the header
names your provider uses (these are Authentik's):

```dotenv
FORWARD_AUTH_ENABLED=true
USERHEADER=X-authentik-username
GROUPHEADER=X-authentik-groups
ADMIN_GROUPS=admin
TRUSTED_PROXY_IPS=172.30.0.2   # the proxy's own address, never a wide range
```

`TRUSTED_PROXY_IPS` and header removal are explained in the
[Reverse proxy guide](/guides/reverse-proxy/#trusted_proxy_ips). Without both settings,
the headers are ignored and nobody can sign in this way. Users are created at their first
request. A forwarded name should match the Jellyfin user name if you sync with Jellyfin.

For Authentik with nginx, every location must either run `auth_request` or blank the
identity headers. The apps check their own credentials on these paths, so they must skip
Authentik: `/j/`, `/subsonic/`, `/api/v1/`, `/oauth/`, `/api/plugin-webhooks/`,
`/api/health` and `/metrics`. Only `/oauth/links/` stays behind it. Gating the whole
domain breaks Jellyfin and Subsonic apps, TV apps, tokens and AirPlay or Chromecast
casting. Copy one bypass block per path:

```nginx
# In the http block: turn an empty groups value into "|" so nginx does not drop it.
map $user $authentik_no_groups { "" ""; default "|"; }
map $groups $authentik_groups_sent { "" $authentik_no_groups; default $groups; }

# In the server block, once per bypass path (/j/, /subsonic/, /api/v1/, /oauth/, /api/plugin-webhooks/):
location ^~ /j/ {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header X-authentik-username "";
    proxy_set_header X-authentik-groups   "";
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For   $remote_addr;
}

# Also keep the web app manifest and icons public, so installing the web app works.
location ~* ^/(manifest\.json|favicon\.(png|ico)|apple-touch-icon(-precomposed)?\.png|icon-(192|512)(-maskable)?\.png)$ {
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header X-authentik-username "";
    proxy_set_header X-authentik-groups   "";
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
}

location / {
    auth_request /outpost.goauthentik.io/auth/nginx;
    error_page 401 = @authentik_signin;
    auth_request_set $user   $upstream_http_x_authentik_username;
    auth_request_set $groups $upstream_http_x_authentik_groups;
    proxy_set_header X-authentik-username $user;
    proxy_set_header X-authentik-groups   $authentik_groups_sent;
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host              $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For   $remote_addr;
}

location ^~ /oauth/links/ {   # same as location / above: needs the signed-in user
    auth_request /outpost.goauthentik.io/auth/nginx;
    error_page 401 = @authentik_signin;
    auth_request_set $user   $upstream_http_x_authentik_username;
    auth_request_set $groups $upstream_http_x_authentik_groups;
    proxy_set_header X-authentik-username $user;
    proxy_set_header X-authentik-groups   $authentik_groups_sent;
    proxy_pass http://127.0.0.1:3000;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_set_header X-Forwarded-For   $remote_addr;
}

location /outpost.goauthentik.io {
    proxy_pass http://your-authentik:9000/outpost.goauthentik.io;
    proxy_set_header Host $host;
    proxy_set_header X-Original-URL $scheme://$http_host$request_uri;
}

location @authentik_signin {
    internal;
    return 302 /outpost.goauthentik.io/start?rd=$scheme://$http_host$request_uri;
}
```

For Traefik, use a `forwardAuth` middleware at
`http://<outpost>:9000/outpost.goauthentik.io/auth/traefik` with the two headers in
`authResponseHeaders`. Apply the same bypass rules.

**A user removed from every group keeps admin.** nginx drops empty headers, so Lumastra
never learns the groups are empty. The `map` lines above fix that. If you cannot change
the proxy, set `FORWARD_AUTH_GROUPS_ALWAYS_SENT=true`, but only when every proxy
location that sends the user name also sends the groups.

**You added OIDC behind a forward-auth proxy.** Let `/auth/oidc/login`,
`/auth/oidc/callback` and `/auth/oidc/backchannel-logout` through unauthenticated.

**Nobody can sign in through forward auth.** Either `FORWARD_AUTH_ENABLED` is off, or
`TRUSTED_PROXY_IPS` does not match the address the proxy connects from. The setup wizard
and the log (`identity headers ignored`) name the address Lumastra saw.

## If something goes wrong

**The install has no admin left.** Restore the admin group at your provider. Or set
`SETUP_UNLOCK=1` in `.env`, restart, and create an admin at `/setup`. Remove the line
afterwards. It works only while no admin exists.

**You turned forward auth on and upgraded from a release before October 2026.** Add
`FORWARD_AUTH_ENABLED=true` before you upgrade, or nobody can sign in.

**An employee or family member leaves.** Disable the account at **Admin → Users**. That
ends their sessions, device tokens, personal tokens and Jellyfin and Subsonic sessions.

**You need tokens for scripts, or want to know how apps sign in.** Apps use the device
flow and `/api/v1` tokens, whatever the browser sign-in method is. See
[API & tokens](/developers/api/) and [OAuth device-flow clients](/developers/oauth-clients/).

**Which identity wins when several methods are on?** A valid session cookie, then forward
auth headers from a trusted proxy, then the `/login` page. If a trusted proxy names a
different user than the cookie, the proxy wins.
