Lumastra listens on port 3000 and speaks plain HTTP. A reverse proxy in front of it
terminates TLS, so your browser and apps connect over HTTPS. This page lists what the
proxy has to do and gives a working setup for the common ones.

## Why you need HTTPS

- **The Apple apps require it.** The iPhone, iPad and Apple TV apps only connect to a
  server on HTTPS with a certificate the device trusts. Plain HTTP and self-signed
  certificates don't work.
- **Login cookies.** The session cookie gets its `Secure` flag only when Lumastra sees
  the request as HTTPS.
- **`ORIGIN` has to match.** Behind a TLS proxy, Lumastra sees plain HTTP unless you
  tell it the public URL. Set `ORIGIN` in your `.env`:

  ```dotenv
  ORIGIN=https://lumastra.example.com
  ```

  Use the exact public address: scheme, host and port (leave the port out if it is 443).
  Restart the stack after changing it. As an alternative you can set
  `PROTOCOL_HEADER=x-forwarded-proto` and `HOST_HEADER=x-forwarded-host`. See
  [Authentication](/guides/authentication/#proxy-trust-fail-closed) for the details.

## What the proxy must do

Every proxy below is set up for this list. If you use another one, check each line.

- [ ] Forward to Lumastra on port 3000 over plain `http://`.
- [ ] Pass the `Host` header through, and set `X-Forwarded-For` and `X-Forwarded-Proto`.
- [ ] Don't buffer streaming responses. Live updates (notifications, watch-state sync,
      Watch Together) use Server-Sent Events, and video is served as HLS segments and
      byte ranges. Lumastra needs no WebSocket support.
- [ ] Allow long read timeouts. A stream or an event connection can stay open for hours,
      and a transcode can take a while to produce its first segment. Lumastra sends a
      keepalive comment about every 10 seconds on event streams.
- [ ] Accept request bodies up to the biggest upload you want, at least the app's
      `BODY_SIZE_LIMIT` (50 MB in the example compose file). The app's own limits are
      10 MB for artwork, 2 MiB for avatars and 3 MiB for diagnostics bundles from the
      iOS and tvOS apps. nginx defaults to 1 MB, which is too small. The full table is
      in [Request body size](/guides/deploy-docker/#request-body-size).
- [ ] Don't compress media or streams. If you enable compression, pick content types
      explicitly. See [Compression](/guides/deploy-docker/#compression).
- [ ] Keep stream tokens and API keys out of the access log. Some apps send them in the
      query string. See
      [Access logs: keep credentials out](/guides/deploy-docker/#access-logs-keep-credentials-out).

## `TRUSTED_PROXY_IPS`

`TRUSTED_PROXY_IPS` lists the addresses of proxies that Lumastra believes. It does two
things:

- It lets those proxies send identity headers for [forward auth](/guides/authentication/#forward-authentication).
  Without it, forward auth does not work.
- It makes Lumastra believe `X-Forwarded-For` from those proxies, so it knows each
  client's real IP address.

If you use built-in or OIDC login and leave it empty, everything still works. Per-IP rate
limits and failed-login counters then give everyone behind the proxy one shared budget,
and a personal access token restricted with `allowed_ips` is compared against the
proxy's address and refused. Set `TRUSTED_PROXY_IPS` to your proxy's address to fix both.
See [Known limitations](/reference/known-limitations/#set-trusted_proxy_ips-if-you-run-behind-a-reverse-proxy).

```dotenv
# Proxy on the same host, reaching Lumastra through the published port
# (see the caution below for what Lumastra sees in that case)
TRUSTED_PROXY_IPS=127.0.0.1,::1
```

:::caution[Which address does Lumastra see?]
Lumastra checks the TCP peer that connects to it. With a proxy installed on the Docker
host, that peer is the compose network's gateway (for example `172.21.0.1`).
Lumastra never sees `127.0.0.1` in that case. Trusting the gateway trusts every process
on the host. For forward auth,
run the proxy as a service in the same compose file and trust only its fixed container
address. The details are in
[Deploy with Docker](/guides/deploy-docker/#reverse-proxy--tls).
:::

## Before you start

- Point a DNS name such as `lumastra.example.com` at your server and open ports 80 and
  443 for certificate issuance and HTTPS.
- Set `ORIGIN` in `.env` as above.
- When the proxy runs on the same host, the example compose file already publishes
  `127.0.0.1:3000:3000`, which is all it needs. When the proxy runs in the same compose
  file, remove the `ports:` block from the `lumastra` service and send traffic to
  `lumastra:3000` over the compose network.
- The example compose file ships Traefik labels with an Authentik forward-auth
  middleware. They do nothing without Traefik. If you use Traefik, replace them as shown
  in the Traefik setup below.

## Setups

Each setup covers a plain proxy. For single sign-on through the proxy, add forward auth
as described in [Authentication](/guides/authentication/) and
[Setting up Authentik](/guides/sso-authentik/), or use
[OIDC](/guides/sso-oidc/), which needs no proxy support at all.

<Tabs>
<TabItem label="Caddy">

Caddy gets and renews certificates by itself. It passes `Host` through, sets
`X-Forwarded-For`, `X-Forwarded-Proto` and `X-Forwarded-Host`, flushes event streams
immediately, and doesn't limit request body size by default. The whole config is:

```caddyfile
lumastra.example.com {
    reverse_proxy 127.0.0.1:3000
}
```

If Caddy runs in the same compose file, point it at the service name instead:

```caddyfile
lumastra.example.com {
    reverse_proxy lumastra:3000
}
```

Add Caddy as a service next to `lumastra`, on the same network, and add the three
volumes at the bottom of the file:

```yaml
services:
  caddy:
    image: caddy:2
    restart: unless-stopped
    ports:
      - '80:80'
      - '443:443'
      - '443:443/udp'
    volumes:
      - ./Caddyfile:/etc/caddy/Caddyfile:ro
      - caddy_data:/data
      - caddy_config:/config
    networks:
      - lumastra-network

volumes:
  caddy_data:
  caddy_config:
```

Caddy writes no access log unless you add a `log` block. If you do, filter the query
string as shown in
[Access logs: keep credentials out](/guides/deploy-docker/#access-logs-keep-credentials-out).

</TabItem>
<TabItem label="nginx">

This is a complete `server` block for a proxy on the same host. Certificates come from
your own setup, for example Certbot. Put the file in `/etc/nginx/conf.d/lumastra.conf`
or your `sites-available` folder.

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name lumastra.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl;
    listen [::]:443 ssl;
    http2 on;   # nginx 1.25.1 or newer; on older versions use "listen 443 ssl http2;"
    server_name lumastra.example.com;

    ssl_certificate     /etc/letsencrypt/live/lumastra.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/lumastra.example.com/privkey.pem;

    # Match the app's BODY_SIZE_LIMIT. nginx defaults to 1 MB.
    client_max_body_size 50m;

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;

        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-For   $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;

        # Live updates and video must not be buffered.
        proxy_buffering off;

        # Streams and event connections stay open for a long time.
        proxy_read_timeout 1h;
        proxy_send_timeout 1h;
    }
}
```

Check and reload:

```bash
sudo nginx -t && sudo systemctl reload nginx
```

nginx writes the full request URI, query string included, to its default access log.
Add the `lumastra_no_query` log format from
[Access logs: keep credentials out](/guides/deploy-docker/#access-logs-keep-credentials-out)
and use it in this `server` block.

If you enable `gzip`, select content types explicitly as described under
[Compression](/guides/deploy-docker/#compression), and leave out `text/event-stream`,
video, audio and HLS.

</TabItem>
<TabItem label="Traefik">

Traefik reads its routing from Docker labels. Put them on the `lumastra` service and
remove the `ports:` block. Traefik and Lumastra must share a Docker network, so this
example uses an external network called `proxy`:

```bash
docker network create proxy
```

Replace the Traefik labels in the example compose file with these, and add the `proxy`
network to the service:

```yaml
services:
  lumastra:
    labels:
      - traefik.enable=true
      - traefik.docker.network=proxy
      - traefik.http.routers.lumastra.rule=Host(`lumastra.example.com`)
      - traefik.http.routers.lumastra.entrypoints=websecure
      - traefik.http.routers.lumastra.tls=true
      - traefik.http.routers.lumastra.tls.certresolver=letsencrypt
      - traefik.http.services.lumastra.loadbalancer.server.port=3000
    networks:
      - lumastra-network
      - proxy

networks:
  proxy:
    external: true
```

The router refers to an entrypoint `websecure` and a certificate resolver `letsencrypt`.
Both come from Traefik's own configuration. A minimal Traefik service that defines them
(in its own compose file or in the same one):

```yaml
services:
  traefik:
    image: traefik:v3
    restart: unless-stopped
    command:
      - --providers.docker=true
      - --providers.docker.exposedbydefault=false
      - --entrypoints.web.address=:80
      - --entrypoints.web.http.redirections.entrypoint.to=websecure
      - --entrypoints.web.http.redirections.entrypoint.scheme=https
      - --entrypoints.websecure.address=:443
      - --certificatesresolvers.letsencrypt.acme.email=you@example.com
      - --certificatesresolvers.letsencrypt.acme.storage=/letsencrypt/acme.json
      - --certificatesresolvers.letsencrypt.acme.httpchallenge.entrypoint=web
    ports:
      - '80:80'
      - '443:443'
    volumes:
      - /var/run/docker.sock:/var/run/docker.sock:ro
      - traefik_letsencrypt:/letsencrypt
    networks:
      - proxy

volumes:
  traefik_letsencrypt:

networks:
  proxy:
    external: true
```

Traefik forwards `Host`, sets `X-Forwarded-For` and `X-Forwarded-Proto`, doesn't buffer
responses, and doesn't limit request bodies. It does close a request that takes longer
than the entrypoint's `readTimeout` (60 seconds by default) to arrive, which can cut off
a large upload from a slow connection. To lift that limit, add this to the Traefik
`command:` list:

```yaml
      - --entrypoints.websecure.transport.respondingTimeouts.readTimeout=0
```

To keep credentials out of the access log, drop query parameters. See
[Access logs: keep credentials out](/guides/deploy-docker/#access-logs-keep-credentials-out).

</TabItem>
<TabItem label="Nginx Proxy Manager">

[Nginx Proxy Manager](https://nginxproxymanager.com/) (NPM) is nginx with a web UI.

:::note[We don't recommend Nginx Proxy Manager]
If you are choosing a proxy, Traefik with Docker labels is easier: the setup lives in your
compose file, with no extra config files or UI. NPM builds its nginx configuration from its
own templates, much like the Kubernetes nginx ingress, so settings it doesn't expose are
awkward to add. It also lacks features such as the PROXY protocol. If you already run NPM,
the steps below work.
:::

If you run it as a container, the simplest layout is to add it to the same compose file
as Lumastra, so it can reach the app by service name:

```yaml
services:
  npm:
    image: jc21/nginx-proxy-manager:latest
    restart: unless-stopped
    ports:
      - '80:80'
      - '443:443'
      - '81:81'   # admin UI: don't expose this to the internet
    volumes:
      - npm_data:/data
      - npm_letsencrypt:/etc/letsencrypt
    networks:
      - lumastra-network

volumes:
  npm_data:
  npm_letsencrypt:
```

Remove the `ports:` block from `lumastra`, run `docker compose up -d`, and open the NPM
admin UI on port 81. Then add a proxy host.

On the **Details** tab:

| Field | Value |
| ----- | ----- |
| Domain Names | `lumastra.example.com` |
| Scheme | `http` |
| Forward Hostname / IP | `lumastra` (the service name). If NPM runs outside this compose file, use the host's address and publish port 3000 on it instead. |
| Forward Port | `3000` |
| Cache Assets | Off |
| Block Common Exploits | Off, unless you have tested it with your apps |
| Websockets Support | Optional. Lumastra doesn't use WebSockets. |

On the **SSL** tab, request a new certificate for the domain and turn on **Force SSL**
and **HTTP/2 Support**.

On the **Advanced** tab, paste this into **Custom Nginx Configuration**:

```nginx
# Live updates and video must not be buffered.
proxy_buffering off;

# Streams and event connections stay open for a long time.
proxy_read_timeout 1h;
proxy_send_timeout 1h;

# Match the app's BODY_SIZE_LIMIT.
client_max_body_size 50m;
```

NPM's proxy hosts already pass `Host`, `X-Forwarded-For` and `X-Forwarded-Proto` to the
upstream. NPM's own access log is per proxy host. Check it for query strings that hold
tokens, as described in
[Access logs: keep credentials out](/guides/deploy-docker/#access-logs-keep-credentials-out).

## Check it works

1. Check the health endpoint through the proxy:

   ```bash
   curl -i https://lumastra.example.com/api/health
   ```

   You should see `HTTP/2 200` (or `HTTP/1.1 200`) and the body `{"status":"pass"}`.
   `curl` fails with a certificate error if the certificate is missing or untrusted.
   Fix that before you try an app.

2. Open `https://lumastra.example.com` in a browser. The address bar should show a
   valid certificate.
3. Sign in. If you are still on first setup, finish the wizard at `/setup`. A login that
   works and stays signed in means `ORIGIN` and the forwarded headers are right.
4. Open the browser's network tools and look at the event stream request. It should stay
   open and show a `: ping` line about every 10 seconds.
5. Sign in from the iPhone, iPad or Apple TV app using your public HTTPS address.

## Common problems

**502 Bad Gateway.** The proxy can't reach Lumastra. Check these in order:

- The upstream must be `http://`, not `https://`, and must use port 3000.
- If the proxy runs in a container, `127.0.0.1` points at the proxy container itself.
  Use the service name `lumastra` on a shared network, or the host's address.
- If the proxy runs on the host, make sure the `ports:` mapping on `lumastra` is still
  there.
- Run `docker compose ps` and check that `lumastra` is healthy.

**Login fails with 403, or the page keeps redirecting.** `ORIGIN` doesn't match the
address in your browser. Compare the scheme, host and port character by character, then
restart Lumastra. Also check that your proxy passes the `Host` header through.

**The login works but you are signed out on the next request.** The session cookie
didn't get its `Secure` flag, usually because `ORIGIN` is unset. Set it and restart.

**Live updates arrive late or never.** The proxy is buffering or compressing event
streams. Turn off buffering for the Lumastra location (`proxy_buffering off` in nginx),
and exclude `text/event-stream` from compression.

**Playback stops after about a minute.** A read timeout is too short. nginx waits
60 seconds by default between two reads from Lumastra, so raise `proxy_read_timeout`.
On Traefik, check the entrypoint timeouts.

**Uploads fail with 413.** The proxy's body limit is smaller than the upload. Raise
`client_max_body_size` in nginx (or its equivalent), to at least `BODY_SIZE_LIMIT`.

**Everyone shares one rate limit, or a token with `allowed_ips` is refused.** Lumastra
sees only the proxy's address. Set `TRUSTED_PROXY_IPS` as described above.

**The Apple app can't connect.** Open your address in Safari on the same device. If it
shows a certificate warning, the app fails too. Use a certificate from a public
authority such as Let's Encrypt.
