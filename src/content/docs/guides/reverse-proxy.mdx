Lumastra speaks plain HTTP on port 3000. A reverse proxy in front of it adds HTTPS. The
iPhone, iPad and Apple TV apps only connect to HTTPS addresses with a certificate the
device trusts.

## 1. Prepare

Point a DNS name such as `media.example.com` at your server and open ports 80 and 443.
Use a name of its own: a subpath such as `example.com/lumastra/` is not supported.

Then set `ORIGIN` to your public address, in the folder with your `.env`:

```bash
sed -i.bak 's|^# ORIGIN=.*|ORIGIN=https://media.example.com|' .env && rm -f .env.bak
docker compose up -d
```

## 2. Set up the proxy

Every setup below forwards to port 3000, passes `X-Forwarded-For` and
`X-Forwarded-Proto`, does not buffer streams, allows long timeouts and large uploads
(the app accepts 50 MB), and removes the sign-in headers (see [below](#sign-in-headers)).
If you have no proxy yet, use Caddy: it gets certificates by itself.

<Tabs>
<TabItem label="Caddy">

Install [Caddy](https://caddyserver.com/docs/install) on the host. Put this in
`/etc/caddy/Caddyfile`, then run `sudo systemctl reload caddy`:

```caddyfile
media.example.com {
    reverse_proxy 127.0.0.1:3000 {
        header_up -X-Forwarded-User
        header_up -X-Forwarded-Groups
        header_up -X-Authentik-Name
    }
}
```

Leave `TRUSTED_PROXY_IPS` empty. Keep the `ports:` block of the `lumastra` service.

</TabItem>
<TabItem label="nginx">

Install nginx and Certbot on the host, then get the certificate first, because nginx
refuses to start with a missing certificate file:

```bash
sudo certbot certonly --nginx -d media.example.com
```

Put this in `/etc/nginx/conf.d/lumastra.conf`, then run
`sudo nginx -t && sudo systemctl reload nginx`:

```nginx
server {
    listen 80;
    listen [::]:80;
    server_name media.example.com;
    return 301 https://$host$request_uri;
}

server {
    listen 443 ssl http2;
    listen [::]:443 ssl http2;
    server_name media.example.com;

    ssl_certificate     /etc/letsencrypt/live/media.example.com/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/media.example.com/privkey.pem;

    client_max_body_size 50m;   # nginx defaults to 1 MB
    send_timeout 1h;            # a paused player stops reading

    location / {
        proxy_pass http://127.0.0.1:3000;
        proxy_http_version 1.1;
        proxy_set_header Host              $host;
        proxy_set_header X-Forwarded-For   $remote_addr;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header X-Forwarded-User   "";
        proxy_set_header X-Forwarded-Groups "";
        proxy_set_header X-Authentik-Name   "";
        proxy_buffering off;
        proxy_read_timeout 1h;
        proxy_send_timeout 1h;
    }
}
```

Leave `TRUSTED_PROXY_IPS` empty. Keep the `ports:` block of the `lumastra` service.

</TabItem>
<TabItem label="Traefik">

Traefik runs in Docker. Create a network with a fixed subnet, so Traefik gets an address
of its own:

```bash
docker network create --subnet 172.30.0.0/24 --ip-range 172.30.0.128/25 proxy
```

In `docker-compose.yml`, delete the `ports:` block and the Traefik labels of the
`lumastra` service, and add this to the file:

```yaml
services:
    lumastra:
        labels:
            - traefik.enable=true
            - traefik.docker.network=proxy
            - traefik.http.routers.lumastra.rule=Host(`media.example.com`)
            - traefik.http.routers.lumastra.entrypoints=websecure
            - traefik.http.routers.lumastra.tls=true
            - traefik.http.routers.lumastra.tls.certresolver=letsencrypt
            - traefik.http.routers.lumastra.middlewares=lumastra-headers
            - traefik.http.middlewares.lumastra-headers.headers.customrequestheaders.X-Forwarded-User=
            - traefik.http.middlewares.lumastra-headers.headers.customrequestheaders.X-Forwarded-Groups=
            - traefik.http.middlewares.lumastra-headers.headers.customrequestheaders.X-Authentik-Name=
            - traefik.http.services.lumastra.loadbalancer.server.port=3000
        networks: [lumastra-network, proxy] # add proxy to the networks it already has
    traefik:
        image: traefik:v3
        restart: unless-stopped
        command:
            - --providers.docker=true
            - --providers.docker.exposedbydefault=false
            - --entrypoints.web.address=:80
            - --entrypoints.web.http.redirections.entrypoint.to=websecure
            - --entrypoints.web.http.redirections.entrypoint.scheme=https
            - --entrypoints.websecure.address=:443
            - --entrypoints.websecure.transport.respondingTimeouts.readTimeout=0
            - --certificatesresolvers.letsencrypt.acme.email=you@example.com
            - --certificatesresolvers.letsencrypt.acme.storage=/letsencrypt/acme.json
            - --certificatesresolvers.letsencrypt.acme.httpchallenge.entrypoint=web
        ports: ['80:80', '443:443']
        volumes:
            - /var/run/docker.sock:/var/run/docker.sock:ro
            - traefik_letsencrypt:/letsencrypt
        networks:
            proxy:
                ipv4_address: 172.30.0.2

volumes:
    traefik_letsencrypt:

networks:
    proxy:
        external: true
```

Set `TRUSTED_PROXY_IPS=172.30.0.2` in `.env` and run `docker compose up -d`. If
`172.30.0.0/24` is taken, pick another private range and change all three addresses.

## 3. Check that it works

1. Run `curl -i https://media.example.com/api/health`. You should see `200` and
   `{"status":"pass"}`. A certificate error means the certificate is missing or untrusted.
2. Run the next command. It must print `401`. A `200` means anyone can sign in as any
   user: stop and fix the proxy.

   ```bash
   curl -s -o /dev/null -w '%{http_code}\n' -H 'X-Forwarded-User: admin' https://media.example.com/api/me
   ```

3. Open `https://media.example.com`. The browser should show a valid certificate and the
   sign-in or setup page. Sign in and reload: you should stay signed in.
4. Sign in from the Apple app with the same address.

## If something differs

### Sign-in headers

With [forward auth](/guides/authentication/#if-you-use-forward-authentication), the proxy
tells Lumastra who the user is in `X-Forwarded-User`, `X-Forwarded-Groups` and
`X-Authentik-Name`. A proxy forwards headers it does not know. If it does not remove the
client's copies, anyone can send `X-Forwarded-User: admin`. Keep those lines in your
config. If you changed `USERHEADER`, `GROUPHEADER` or `NAMEHEADER`, remove those names.

### TRUSTED_PROXY_IPS

This list names the proxies Lumastra believes: it reads their `X-Forwarded-For` for the
real client address, and with `FORWARD_AUTH_ENABLED=true` their sign-in headers. Empty is
safe but every client then looks like the proxy.

- A proxy in the same compose file: give it a fixed address and list only that address.
- A proxy installed on the Docker host: leave it empty. Lumastra sees the network
  gateway, which every program on the host shares.
- Never list a range wider than `/24`. With forward auth on, every address in it could
  sign in as any user. List every proxy hop, or let the inner proxy restore the client
  address and list only that one.

**You use Cloudflare in front of nginx.** Add one `set_real_ip_from` line per range from
[cloudflare.com/ips](https://www.cloudflare.com/ips/) to the `server` block:

```nginx
    set_real_ip_from 173.245.48.0/20;
    # ... the remaining ranges ...
    real_ip_header CF-Connecting-IP;
```

**You use another proxy.** It must forward every path to Lumastra: `/api/v1/`, `/oauth/`,
`/j`, `/subsonic/`, `/api/plugin-webhooks/`, `/api/health`, `/metrics` and `/manifest.json`.
Apps check their own credentials there. If an auth layer such as Authentik sits in front,
those paths must skip it. Nginx Proxy Manager works with the nginx lines above in its
**Advanced** tab.

### Keep credentials out of access logs

Apps send tokens in the query string, so log paths without it. In
Traefik: `--accesslog.fields.queryparameters.defaultmode=drop` (3.7.3 or newer). nginx and
Caddy need a log format without the query string.

**You enable compression.** Name the content types, and leave out `text/event-stream`,
video, audio and HLS.

### Common problems

**502 Bad Gateway.** The upstream must be `http://` on port 3000. A proxy in a container
cannot use `127.0.0.1`: use the service name `lumastra`. Run `docker compose ps`.

**504 on Traefik.** It picked the wrong network. Keep the `traefik.docker.network=proxy`
label.

**Login fails with 403.** `ORIGIN` differs from the browser address. Remove any `:3000`
and restart.

**Sign-in works, then you land on the sign-in page again.** You opened the `http://`
address while `ORIGIN` is `https://`. Use the HTTPS address.

**Live updates arrive late, or playback stops after a pause.** Turn buffering off and raise
the proxy timeouts.

**Uploads fail with 413.** Raise the proxy's body limit to at least 50 MB.

**The Apple app cannot connect.** Open your address in Safari on that device. A
certificate warning there fails in the app too. Use a public certificate.
