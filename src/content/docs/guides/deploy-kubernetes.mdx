---
title: Deploy on Kubernetes
description: Install Lumastra on Kubernetes with the Helm chart. One node, a managed PostgreSQL, an Ingress and your media folder, in about ten steps.
---

The Helm chart runs Lumastra as web pods, one worker, two Valkeys and a PostgreSQL
database. This page installs the smallest useful setup: one node, a database that
CloudNativePG manages for you, and an Ingress. For several web pods, shared storage,
GPUs and other options, see [Advanced Kubernetes](/guides/deploy-kubernetes-advanced/).
Docker Compose is the other fully supported way to run Lumastra: see the
[Quick Start](/start/quick-start/).

## What you need

- Kubernetes 1.29 or newer, with `kubectl` and `helm` working. `kubectl get nodes` should
  list your node as `Ready`.
- An Ingress controller. k3s ships Traefik.
- A folder with your media on the node.
- A DNS name that points at the node. Without one, see the end of this page.

No cluster yet? A single machine is enough. See "You have no cluster" below.

## 1. Choose your settings

Set these once. The next steps use them.

```bash
export LUMASTRA_HOST=media.example.com   # the address people will type
export MEDIA_DIR=/srv/media              # your media folder on the node
export INGRESS_CLASS=traefik             # "nginx" for ingress-nginx; see: kubectl get ingressclass
export NODE=$(kubectl get nodes -o jsonpath='{.items[0].metadata.name}')
```

With more than one node, set `NODE` to the node that has the media folder.

## 2. Get the chart

```bash
git clone --branch v0.1.4 https://github.com/Sapd/lumastra
cd lumastra
```

You should now see `deploy/helm/lumastra`.

## 3. Install the database operator

CloudNativePG creates a PostgreSQL 18 database with pgvector and the other extensions
Lumastra needs. Install its operator once per cluster:

```bash
helm repo add cnpg https://cloudnative-pg.github.io/charts
helm upgrade --install cnpg cnpg/cloudnative-pg -n cnpg-system --create-namespace --wait
```

You should see `STATUS: deployed`.

## 4. Create the secrets

```bash
kubectl create namespace lumastra
kubectl -n lumastra create secret generic lumastra \
  --from-literal=LUMASTRA_MASTER_KEY="$(openssl rand -hex 32)" \
  --from-literal=CACHE_PASSWORD="$(openssl rand -hex 24)"
```

Print the master key and store it outside the cluster. Without it, stored API keys cannot
be decrypted.

```bash
kubectl -n lumastra get secret lumastra -o jsonpath='{.data.LUMASTRA_MASTER_KEY}' | base64 -d; echo
```

## 5. Write the values file

```bash
cat > my-values.yaml <<EOF
mode: split

image:
  tag: 0.1.4

app:
  origin: http://$LUMASTRA_HOST

secrets:
  existingSecret: lumastra

web:
  replicas: 1

router:
  enabled: false

global:
  nodeSelector:
    kubernetes.io/hostname: $NODE

database:
  mode: cnpg

persistence:
  config:
    accessModes: [ReadWriteOnce]
  transcode:
    type: emptyDir
    emptyDirSizeLimit: 20Gi
  plugins:
    accessModes: [ReadWriteOnce]
  appCache:
    enabled: true
    accessModes: [ReadWriteOnce]

libraries:
  - name: media
    mountPath: /data/media
    hostPath: $MEDIA_DIR

ingress:
  enabled: true
  className: $INGRESS_CLASS
  hosts:
    - host: $LUMASTRA_HOST
EOF
```

`grep host: my-values.yaml` should show your host name. This keeps every pod on one node, so the volumes need only `ReadWriteOnce` and no router
is needed. Volume settings cannot change after the first install, so get them right now.
The media folder must be readable by user ID 1000.

## 6. Install

```bash
helm install lumastra ./deploy/helm/lumastra -n lumastra -f my-values.yaml
kubectl -n lumastra get pods -w
```

Stop watching with Ctrl+C. After one to three minutes, the web pod `lumastra-web-0`, the
worker, both Valkeys and the database pod `lumastra-postgres-1` should all be `Running`
and ready.
The first start downloads FFmpeg and migrates the database, and the pods may restart a
few times while the database starts. That is normal.

## 7. Open the setup wizard

Open `http://media.example.com/setup`, with your own host name. You should see **Check
your install**. Create the admin with **Built-in login**, then add your library folders.
The folder shown is `/data/media`. The steps are the same as in the
[Quick Start](/start/quick-start/#5-create-your-admin). The wizard warns that
`TRUSTED_PROXY_IPS` is not set. That is expected here: rate limits then treat all clients
as one. The router in [Advanced Kubernetes](/guides/deploy-kubernetes-advanced/#why-is-there-a-router)
passes the real client address.

## 8. Switch to HTTPS

The Apple apps need HTTPS. The Ingress reads the certificate from a Secret named
`lumastra-tls`. With cert-manager, add
`--set 'ingress.annotations.cert-manager\.io/cluster-issuer=<issuer>'` to the upgrade
command below and it creates the Secret. With your own certificate files, create it
yourself:

```bash
kubectl -n lumastra create secret tls lumastra-tls --cert=fullchain.pem --key=privkey.pem
```

Then point the values at HTTPS and upgrade:

```bash
sed -i.bak 's|origin: http://|origin: https://|' my-values.yaml && rm my-values.yaml.bak
cat >> my-values.yaml <<EOF
  tls:
    - hosts: [$LUMASTRA_HOST]
      secretName: lumastra-tls
EOF
helm upgrade lumastra ./deploy/helm/lumastra -n lumastra -f my-values.yaml
```

Open `https://media.example.com`. The browser should show a valid certificate. Without
the Secret, the Ingress controller serves its own certificate and the browser warns.

## If something differs

**You have no cluster.** On a Linux machine, install k3s and give your user access:

```bash
curl -sfL https://get.k3s.io | sh -
mkdir -p ~/.kube && sudo cp /etc/rancher/k3s/k3s.yaml ~/.kube/config && sudo chown $USER ~/.kube/config
```

Install `helm` from [helm.sh](https://helm.sh/docs/intro/install/).

**You have no DNS name yet.** Add the node's address to the hosts file of the computer you
browse from, for example `203.0.113.10 media.example.com`. The name must match
`app.origin`.

**Pods stay `Pending`.** Run `kubectl -n lumastra get pvc`. A claim stuck in `Pending`
usually means the storage class has no `ReadWriteMany`. Check that the `persistence`
settings from step 5 are in your values file. Volume settings cannot change on an existing
claim: run `helm uninstall lumastra -n lumastra`, delete the empty claims with
`kubectl -n lumastra delete pvc --all` (on a fresh install only: this removes every claim in
the namespace), and install again.

**Your media is on a volume or NFS share, not on the node.** Replace `hostPath` in the
`libraries` entry with one of these:

```yaml
    existingClaim: my-media-claim
    # or
    nfs: { server: 10.0.0.1, path: /export/media }
```

**You run your own PostgreSQL.** Use PostgreSQL 17 or newer. As a superuser, run this in
the Lumastra database, put the connection URL in the `lumastra` Secret as `DATABASE_URL`
and remove `database.mode: cnpg` from the values:

```sql
CREATE EXTENSION IF NOT EXISTS vector WITH SCHEMA public;
CREATE EXTENSION IF NOT EXISTS pg_trgm WITH SCHEMA public;
CREATE EXTENSION IF NOT EXISTS pgcrypto WITH SCHEMA public;
CREATE EXTENSION IF NOT EXISTS unaccent WITH SCHEMA public;
```

**You want more than one web pod, or your nodes share storage.** See
[Advanced Kubernetes](/guides/deploy-kubernetes-advanced/).

**You want to read the logs.**

```bash
kubectl -n lumastra logs -f statefulset/lumastra-web
kubectl -n lumastra logs -f deploy/lumastra-worker
```

**You want to update.** Check out the new tag and put the new version in your values file,
so later upgrades keep it:

```bash
git fetch --tags && git checkout v0.1.5   # example: the release you want
sed -i.bak 's|^  tag: .*|  tag: 0.1.5|' my-values.yaml && rm my-values.yaml.bak
helm upgrade lumastra ./deploy/helm/lumastra -n lumastra -f my-values.yaml
```

Back up the database and your master key first. See
[Backup & recovery](/guides/backup-recovery/).
